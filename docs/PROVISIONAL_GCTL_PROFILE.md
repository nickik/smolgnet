# smolgnet provisional GCTL body profile

## Status

This document describes **implementation-defined smolgnet encodings** used to exercise current GNet GCTL semantics before the canonical GNet specification freezes compact field packing.

It is not a GNet ADR and must not be treated as a frozen protocol wire format.

The canonical items already defined by GNet remain unchanged:

- GCTL is GDP Type `0x1`;
- the common GCMP header is 8 bytes;
- GCTL message type registry values are unchanged;
- `CREDIT_REQUEST` and `CREDIT` are carried on the normal data path;
- one link credit represents receive capacity for one physical flit at the adjacent forwarding endpoint;
- Router discovery uses `SOLICIT` / `ADVERTISE`;
- address configuration uses `ADDRESS_OFFER` / `ADDRESS_CLAIM` / `ADDRESS_ACK` / `ADDRESS_NAK`;
- delegated prefix lengths in the current profile are `/16`, `/32`, `/48`, or `/56`;
- clients have FE80/16 link-local GDP addresses before routed address assignment.

## Common GCMP header

All messages retain the existing common GCTL header:

```text
Version          1 byte
Message Type     1 byte
Code             1 byte
Flags            1 byte
Transaction ID   4 bytes
```

Multi-byte provisional body values use network byte order. Unused bytes in the selected GDP Size Class are zero padding and parsers reject nonzero padding for typed provisional messages.

## CREDIT_REQUEST

```text
Requested Flits   4 bytes
```

A value of zero means "advertise whatever receive capacity is currently grantable".

## CREDIT

```text
Granted Flits     4 bytes
```

The receiver must never advertise more flits than its real free receive capacity minus previously advertised-but-not-yet-consumed credit.

## SOLICIT

```text
Service Type      2 bytes
Scope             1 byte
Reserved          1 byte = 0
```

Current smolgnet scope `0` means directly attached/link scope.

## ADVERTISE

```text
Service Type      2 bytes
Preference        1 byte
Reserved          1 byte = 0
Provider Address  8 bytes
Lifetime          4 bytes
Capabilities      4 bytes
```

`Service Type = 0x0001` identifies Router.

## ADDRESS_OFFER

```text
Router Address    8 bytes
Prefix            8 bytes
Prefix Length     1 byte
Reserved          3 bytes = 0
Candidate Address 8 bytes
Lifetime          4 bytes
```

The Prefix must be normalized and Prefix Length must be one of `/16`, `/32`, `/48`, or `/56`. Candidate Address must lie inside Prefix.

## ADDRESS_CLAIM

```text
Candidate Address 8 bytes
Claim Nonce       8 bytes
```

## ADDRESS_ACK

```text
Confirmed Address 8 bytes
Lifetime          4 bytes
```

## ADDRESS_NAK

```text
Candidate Address 8 bytes
Retry Delay       4 bytes
```

The common GCMP `Code` field carries the rejection reason.

## Point-to-point bootstrap destination

The canonical specification currently leaves the pre-assignment bootstrap GDP destination representation open.

smolgnet temporarily reserves:

```text
FE80:0000:0000:0000
```

as the point-to-point discovery destination for an initial `SOLICIT` when the provider address is not yet known.

Normal FE80/16 client link-local addresses always use a nonzero 48-bit suffix, so this value cannot collide with a normal client generated by `Endpoint::unconfigured`.

Once an `ADVERTISE`/`ADDRESS_OFFER` identifies the authority, subsequent claim/ack traffic is directed to actual link-local endpoint addresses.

## Link-buffer credit model

Each `EndpointConfig` supplies `rx_buffer_flits`.

For ordinary data traffic:

```text
free = rx_buffer_flits - flits currently retained in DLP receive assembly

grantable = free - credits already advertised but not yet consumed
```

A received data flit:

1. must have one previously advertised peer credit;
2. consumes that credit;
3. consumes one unit of receive storage;
4. remains in DLP receive assembly until its GDP packet is complete;
5. releases receive storage when the complete packet is handed upward;
6. causes newly grantable capacity to be advertised with GCTL CREDIT according to the endpoint threshold.

This gives a direct relationship between actual bounded receive storage and advertised physical-flit capacity.

## Reserved control lane

smolgnet's current direct point-to-point DLP profile reserves VC 0 for GCTL/control traffic and gives it a small statically provisioned sliding receive window.

This prevents a deadlock where a sender needs a CREDIT message in order to gain enough credit to receive that same CREDIT message.

Ordinary advertised DLP receive credit applies to the aggregate data lanes, not separately to each VCID.

With `VcMode::Two`:

```text
VC0   control
VC1   data
```

With `VcMode::Four`:

```text
VC0   control
VC1-3 data
```

GDP, GCTL application functions, and GTS do not select numeric data VCIDs. DLP assigns them internally.

This reserved-control-lane rule is a smolgnet point-to-point implementation mechanism and should remain isolated so a later native link profile or frozen GNet rule can replace it without altering GDP/GCTL/GTS APIs.
